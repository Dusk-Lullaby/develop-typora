# 03_操作系统软件视角

## 1. CPU运行模式

操作系统的核心目的是为了完全地管理硬件。为了防止普通应用程序恶意破坏系统或直接操作硬件，CPU 在硬件层面提供了两种工作方式：

*   **内核模式（特权模式）：**

    具有最高权限，操作系统的核心代码在此模式下运行，可以直接操控驱动和硬件

*   **用户模式（无特权模式）：**

    普通应用程序运行的模式。它们被隔离在一个受限的环境中，可以看作是操作系统管理的一个子对象

    

## 2. 系统调用的软中断机制

<font color = "red">**系统调用是跨越模式的唯一渠道**</font>

当用户模式下的程序需要执行特权操作（如读写文件、分配内存）时，不能直接调用内核代码，必须通过”系统调用“来切换模式

### 2.1 普通函数与特殊函数底层差异

*   普通函数（如`printf`）：

    在用户通过修改PC（Program Counter， 程序计数器）指针直接跳转（`jump pc = printf`）执行

*   特殊函数（如`open,read,write`）：依赖系统调用。高级语言经过编译器翻译成汇编语言时，会插入特定的软中断指令（如ARM架构下的 `swi` 指令）

### 2.2 分发机制

每个系统调用都有一个对应的编号（如`swi 0x1, swi 0x5`）。陷入内核后，操作系统内核中存在一个类似于`switch(num)`的对应读操作



## 3. 中断与异常的底层处理管线（``Pipline`）

系统调用本质是利用了硬件的异常机制。操作系统将硬件提供的中断和异常机制统一管理起来

### 3.1 中断与异常

*   中断（外中断）

    外部硬件触发的异步事件。例如，在执行指令A期间发生中断，下一个时钟周期 CPU 发现中断，此时 PC 指针已经指向B。CPU会保存指令B的地址，先去处理中断，处理完成再恢复执行指令B

*   异常（内中断）

    指令执行过程中触发的同步事件。包含有意安排的陷阱（如上述的`swi`软中断指令触发系统调用）以及错误（如 `a/0`除0异常、缺页异常）

### 3.2 标准处理生命周期

1.   触发与保存：异常或中断发生时，硬件自动保存当前程序的”断点“（下一条指令的地址）和”程序状态字“（寄存器状态）
2.   跳转入口：CPU 自动跳转到预言设定好的异常/中断入口地址
3.   保护现场：操作系统接管，将当前CPU通用寄存器中的数据压入内核栈中，防止被后续处理程序覆盖
4.   执行处理：执行具体的中断服务程序（`ISR`）或系统调用逻辑
5.   恢复现场：从内核栈中弹出之前保存的寄存器数据
6.   开中断与恢复断点：重新允许中断响应，并将保存的断点地址恢复到PC寄存器中，程序返回用户状态继续执行



## 4. 进程的虚拟内存空间布局

为了避免多个`App`直接访问和篡改物理内存导致系统崩溃，操作系统为每个进程提供了一个独立的“虚拟地址空间”。

以 32-bit 系统为例，每个进程认为自己独占 `4GB`（2^32 字节）的内存地址，其标准的线性布局自顶向下依次为：

*   内核区：占据最高位地址，存放操作系统核心代码、驱动等。所有用户进程共享这一物理内存的映射，但用户程序无权直接访问该区域
*   栈区（stack）：存放函数的局部变量、参数和返回地址。由高地址向低地址向上生长
*   堆区（heap）：存放通过`malloc`等动态分配的内存。由地址向高地址向上生长
*   .boss 段：存放未初始化的全局变量和静态变量
*   .data 段：存放已经初始化的全局变量和静态变量
*   .text段（代码段）：存放编译后的机器指令（即只读的程序逻辑）
*   不能访问区：最底部的保留区域。这是一种保护机制，任何试图读写地址0（空指针 NULL）的操作都会落入此区域，立刻发生段错误异常，从而终止程序，防止非法内存访问。
