# 权限修饰符

作用范围：private  < 空着/缺省/默认 < protected < public



|       修饰符       | 同一个类中 | 同一个包中其他类 | 不同包下的子类 | 不同包下的无关类 |
| :----------------: | :--------: | :--------------: | :------------: | :--------------: |
|      private       |     √      |                  |                |                  |
| 空着不写/缺省/默认 |     √      |        √         |                |                  |
|     protected      |     √      |        √         |       √        |                  |
|       public       |     √      |        √         |       √        |        √         |



## 权限修饰符使用规则

实际开发中，一般只用public和private

* 成员变量私有
* 方法公开
* 特例：如果方法中的代码是抽取其他方法中共性的代码，这个方法一般也私有



# 代码块



## 局部代码块

局部代码块可以节约内存，但已经渐渐淘汰了

指写在方法中的代码，也可以理解为大括号范围，比如

```java
public class Test {
    public static void main(String[] args) {

        
        
        //这一部分就是局部代码块
        //只有在这一局部才可以使用变量a
        {
            int a = 10;
            System.out.println(a);
        }
        
        //System.out.println(a);	报错，a已经消失了
        
        

    }
}
```



## 构造代码块

1. 写在成员位置的代码块

2. 作用：可以把多个构造方法中重复的代码抽取出来

3. 执行时机：我们在创建本类对象的时候会先执行构造代码块再执行方法

   也就是，构造代码块优先于构造方法执行



对于这段代码，在两个构造方法中，有重复的部分，即打印"开始创建对象"

可以把这部分抽取出来，变为构造代码块

```java
public class Students {
    private String name;
    private int age;
    
    public Students() {
        System.out.println("开始创建对象");
    }
    
    public Students(String name, int age) {
        System.out.println("开始创建对象");
        this.name = name;
        this.age = age;
    }
}
```



转变为构造代码块

```java
public class Students {
    private String name;
    private int age;

    //构造代码块
    {
        System.out.println("开始创建对象");
    }
    
    public Students() {
//        System.out.println("开始创建对象");
    }

    public Students(String name, int age) {
//        System.out.println("开始创建对象");
        this.name = name;
        this.age = age;
    }
}
```



那么如何验证是先执行构造代码块还是先执行构造方法呢？

可以在构造方法中加入一些输出语句，从而验证，比如

```java
public class Students {
    private String name;
    private int age;

    //构造代码块
    {
        System.out.println("开始创建对象");
    }

    public Students() {
//        System.out.println("开始创建对象");
        System.out.println("无参");
    }

    public Students(String name, int age) {
//        System.out.println("开始创建对象");
        this.name = name;
        this.age = age;
        System.out.println("有参");
    }
}
```

```java
    public static void main(String[] args) {
        Students s1 = new Students();
        Students s2 = new Students("zhangsan", 82);
    }

```

其输出结果为：

开始创建对象
无参
开始创建对象
有参

因此，构造代码块优先于构造方法执行



但该技术也已经渐渐淘汰了，主要为不够灵活，很死

比如，当我有第三个构造方法，不想输出"开始创建对象"，但仍会执行构造代码块



那么如何改善呢？

可以将有重复的构造方法，通过this关键字，调用本类其他构造，写在一个构造方法中

比如：

```java
public class Students {
    private String name;
    private int age;
    
    public Students() {
        this(null, 0);	//通过this关键字，调用本类其他方法
    }
    
    public Students(String name, int age) {
        System.out.println("开始创建对象");
        this.name = name;
        this.age = age;
    }
}
```

当然除了这种方式，还可以将"开始创建对象",抽取为一种方法

在使用构造方法时，直接调用方法就行



因此，当构造方法中有重复内容时，可以采用以上2种，构造代码块了解即可



## 静态代码块（重点）

格式：static{}

特点：需要通过static关键字修饰，随着类的加载而加载，并且自动触发，只执行一次

使用场景：在类的加载的时候，做一些数据初始化的时候用



与构造代码块进行对比

构造代码块在每一次创建对象时都会执行，创建了10个对象，就行执行10次

而静态代码块，只会执行一次

比如，

```java
    //执行时机：
    //随着类的加载而加载，并且只执行一次
	static{
        System.out.println("静态代码块执行了");
    }



    public Students() {
//        System.out.println("开始创建对象");
        System.out.println("无参");
    }

    public Students(String name, int age) {
//        System.out.println("开始创建对象");
        this.name = name;
        this.age = age;
        System.out.println("有参");
    }

```

```java
    public static void main(String[] args) {
        Students s1 = new Students();
        Students s2 = new Students("zhangsan", 82);
    }

```

其执行结果为：

静态代码块执行了
无参
有参

因此，优先执行静态代码块，且仅执行了一次



## 总结

1. 代码块的分类：局部代码块，构造代码块，静态代码块
2. 局部代码块的作用：提前结束变量的生命周期（淘汰）
3. 构造代码块的作用：抽取构造方法中的重复代码（不够灵活）
4. 静态代码块的作用：数据的初始化（重点）
